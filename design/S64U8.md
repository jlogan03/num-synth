# S64U8: fixed-width working arithmetic for f64-class workloads

## Goal and API

The goal is arithmetic with at least binary64's range and resolution using
small-width integer operations, including on devices without native f64
arithmetic. `S64U8` is a fixed-width number with its own finite precision and
exponent limits. It is the value passed between operations, not an arbitrary-
length exact accumulator. The earlier 68-bit stage and `S64I8` API are replaced.

```rust
use num_synth::S64U8;

let a = S64U8::from_f64(1.25);
let b = S64U8::from_f32(0.5);
let c = (a + b) * a;          // Remains in the working representation.
let fused = a.mul_add(b, c); // One working-precision rounding.
let output64 = fused.to_f64();
let output32 = fused.to_f32();
```

`+`, `-`, `*`, negation, comparisons, and `mul_add` operate on and return the
working type. There are no arithmetic `_f64` variants or alternate output
modes on arithmetic operations. `to_f64` and `to_f32` explicitly round the
stored value to their respective output formats. The `From` conversions are
equivalent. `from_bits`/`to_bits` use binary64 encodings;
`from_f32_bits`/`to_f32_bits` use binary32 encodings.

The 32-byte working significand has 256 bits of precision. An operation rounds
to nearest-even when its result exceeds that capacity, just as other fixed-
width floating-point formats do. That precision is a property of this chosen
storage, not a requirement that every future backend use 256 bits. Smaller
formats can be considered when their resolution and throughput justify them;
there is no mandatory 68-bit normalization step.

Standalone conversion rounds the represented working value. It does not
reconstruct an earlier operation's discarded bits or promise bit-identical
IEEE results after a chain of operations. No provenance or residual is carried
between operations. In particular, `to_f32` rounds directly from the working
value rather than through f64. GPU throughput is not yet benchmarked; the full
32-by-32 product costs 1024 digit multiplications.

## Representation, uniqueness, precision, and range

Finite nonzero values use unsigned, little-endian radix-256 digits:

```text
S = sum(d[i] * 256^i), i = 0,...,31
0 <= d[i] <= 255
128 <= d[31] <= 255
2^255 <= S < 2^256
x = (-1)^negative * S * 2^(E - 255)
E is an i16, from -32768 through 32767
```

The 32-byte array is the significand, not the whole object. The `#[repr(C)]`
object occupies 36 bytes: an `i16` exponent, `[u8; 32]`, a `#[repr(u8)]`
classification, and a sign `bool`. Private fields enforce invariants. Raw
object bytes are not a serialization or device ABI contract.

Ordinary base-256 expansion is unique because each digit is the unique residue
modulo 256, followed by integer division and induction. The high-bit condition
makes `E = floor(log2(abs(x)))` unique. Every integer in `[2^255,2^256)` is
representable, hence precision is exactly 256 bits and binade spacing is
`2^(E-255)`. Within range, nearest rounding has relative error at most `2^-256`.
This supplies 203 significand bits beyond binary64's 53.

```text
smallest positive = 2^-32768
largest finite magnitude = (2 - 2^-255) * 2^32767
```

All binary64 finite inputs fit exactly. For a normal binary64 mantissa `m`
with 53 bits, use `S = m << 203` and its unbiased exponent. For subnormals,
let `k = floor(log2(fraction))`, use `S = fraction << (255-k)` and
`E = k-1074`. These exponents are between -1074 and 1023. Binary32 uses the
same construction with 24-bit mantissas, subnormal quantum `2^-149`, and
exponents from -149 through 127. Expansion uses only integer bit operations.

## Classification and exceptional values

Classification is zero, finite, infinity, or NaN. There is no internal subnormal
class. Zero and infinity have exponent zero and zero digits. NaNs also have
exponent zero; their low eight digits encode the original nonzero binary64
fraction, and the other digits are zero. Sign is independent for every class.

Conversions preserve all binary64 bit patterns, including signaling NaNs.
Binary32 NaN fractions are shifted left 29 bits on input, aligning their quiet
bit with binary64 bit 51. Converting back shifts right 29; if narrowing would
remove the whole payload, fraction 1 preserves NaN classification. Thus every
binary32 encoding also round-trips. Conversions do not quiet NaNs.

Arithmetic quiets the first NaN in original argument order while retaining
its sign and remaining payload. This takes precedence over other invalid
cases, including `0 * infinity + NaN`. Without NaN inputs, invalid operations
such as `0 * infinity`, opposite infinities added, or an infinite product plus
its opposite infinity return `0x7ff8_0000_0000_0000`.

Multiplication uses the XOR of signs. Same-sign zeros added retain their sign;
opposite signs and exact cancellation produce positive zero. Subtraction
negates the right operand after checking NaN propagation. FMA applies the same
addition rule to the unrounded product and addend. Negation only toggles the
sign, even for NaNs. Signed zeros compare equal; NaNs are unordered and unequal
to every value. Finite comparison uses the full exponent and all 32 digits.

Overflow uses the midpoint between the largest finite value and the virtual
successor `2^32768`; the tie rounds to infinity. Underflow rounds to the nearer
of zero and `2^-32768`; the midpoint `2^-32769` rounds to zero. The exact
result's sign survives underflow. There are no exception flags.

## Fixed scratch storage and accumulator proofs

The canonical working value is `[u8; 32]`. Each arithmetic scratch integer is
a fixed `[u8; 66]`: 528 bits, sufficient for a full 512-bit product and 16
extra bits of alignment/carry space. There is no dynamic storage, length field,
trimming loop, native floating-point arithmetic, or `u128` arithmetic. A
separate output union is unnecessary: operators return `S64U8` directly, with
its own classification bits.

For unsigned digits, a product is in `[0,255^2] = [0,65025]`. Convolution of
32 digits gives 63 coefficients, each with at most 32 terms:

```text
c[k] = sum(a[i] * b[j]), i+j=k
0 <= c[k] <= min(k+1, 63-k, 32) * 65025 <= 2080800
```

Operands are widened to `u32` before multiplication. Both coefficients and
all partial sums fit exactly. Carry propagation emits the low eight bits and
shifts right eight bits. The invariant `carry <= 8160` follows from
`floor((2080800 + 8160)/256) = 8160`. Including carry, the maximum intermediate
is 2088960, below `2^21`. The full product is below `2^512`, so its final carry
fits byte 63; bytes 64 and 65 remain zero. No low product terms are omitted.

Addition uses `u16` limb sums bounded by `255+255+1 = 511`. Subtraction uses
`i16` differences in `[-256,255]`, including borrow. Shift extraction combines
two bytes in `u16`, whose maximum value is 65535. All loops have fixed bounds:
32 working digits, 66 scratch digits, or 32-by-32 products. Classification,
sign, and shift-direction decisions still branch; fixed storage does not
imply entirely branch-free machine code.

## Alignment and cancellation

For addition or FMA, take two exact scratch terms `N_a * 2^P_a` and
`N_b * 2^P_b`, with independent signs. They are newly constructed input
significands or a newly computed product, each with at most 512 significant
bits. Handle zero terms first. Let `T` be the larger leading-bit exponent and
choose shared power `P = T - 526`. The dominant term's leading bit sits at
bit 526; bit 527 is reserved for a carry from addition.

A left shift is exact. A right shift keeps the integer quotient and ORs any
nonzero discarded bits into its low bit:

```text
jam(N,h) = floor(N / 2^h) | ((N mod 2^h) != 0)
```

If nothing is discarded, this is exact. Otherwise the surrogate is odd and
its error is strictly less than one scratch unit. Shifts beyond the entire
buffer produce zero or a single sticky bit safely, with the same fixed loop
bounds. Power differences use `i32`, including differences spanning the full
`i16` exponent range.

The dominant term has at least `527-512 = 15` low zero bits. If the exponent
gap is at most 15, the smaller term also fits exactly: its lowest possible bit
is `526-15-511 = 0`. This retains all cancellation bits when the terms are
close. If alignment is inexact, the gap is at least 16, so the smaller term
cannot cause substantial cancellation. The result's leading bit is at least
525, and its sign is the dominant term's sign.

In that inexact case, adding or subtracting an odd surrogate from the even
dominant integer gives an odd result. Rounding it to 256 bits discards at least
270 low bits; all nearest-even midpoints are even integers in scratch units.
The surrogate is at least one unit from any midpoint, and its error is less
than one, so the exact and surrogate results select the same neighbor.
Binade, overflow, and zero/minimum boundaries are also even thresholds here.
Thus jamming preserves correct rounding to the working format, including
opposite-sign subtraction. A jammed scratch value is consumed immediately by
this operation and never reused as an exact operand for another operation.

FMA forms the full product and combines the addend before working-format
rounding or range checks. A product beyond the working exponent range can
therefore cancel to a representable result. The scratch capacity is fixed for
every operation; no exact accumulator grows with an expression chain.

## Working rounding and standalone conversion

For a nonzero scratch magnitude `N` of bit length `b`, the normalized exponent
is `E = P+b-1`. Retain the top 256 bits (left shifting exactly if necessary).
The next bit is guard; sticky is the OR of every lower bit. Increment when
`guard && (sticky || retained_lsb_is_odd)`. A carry out of all 32 digits sets
the significand to `2^255` and increments the exponent. This is equivalent to
comparing the exact quotient remainder with half the divisor and choosing
the even integer at equality. Apply the working exponent limits above.

Standalone conversion applies the same remainder rule to the **stored value**.
For an IEEE destination with `f` stored fraction bits and exponent bias `B`:

* Normal output retains `f+1` bits by rounding `S / 2^(255-f)`.
* Subnormal output uses quantum `2^(1-B-f)`, rounding directly with right shift
  `255-E+1-B-f`. Do not first round to a normal significand.
* A rounding carry increments the exponent; overflow yields infinity.
* A subnormal fraction rounding to `2^f` encodes the smallest normal directly.
* An exact half-minimum-subnormal rounds to signed zero.

Use `(f,B)=(52,1023)` for binary64 and `(23,127)` for binary32. These conversions
use `u64` for IEEE fields and bit assembly only. The working arithmetic uses
byte digits and `u16`/`u32` accumulators. The library is unconditionally
`no_std`, uses only `core`, and has no production dependencies. It does not
link `alloc` or require a global allocator; fixed-size storage is the runtime
contract for embedded and GPU compatibility. Host-side development dependencies
provide the test oracles separately.

## Verification

Test-only `num-bigint` computes exact sums/products and independently rounds
them by quotient/remainder to the 256-bit grid. Properties cover arbitrary
full-width significands, the entire `i16` exponent domain, chains with rounding
at each working operation, alignment cutoffs, sign combinations, and FMA
cancellation against the rounded product. Directed tests demonstrate retention
of `2^-200` through a chain and recovery of a `2^-510` product residual in FMA.

A separate conversion oracle searches adjacent IEEE encodings on an exact
integer lattice, compares distances, and breaks ties by encoding parity.
Properties check both destinations and arbitrary input bit patterns through
random sampling, plus every exponent field with boundary fractions. Directed tests
cover signed zeros, NaN payloads, signaling bits, both rounding parities,
subnormal transitions, range limits, and direct f32 conversion that would
otherwise double round through f64.

Run `cargo test`, `cargo test --release`, `cargo fmt --check`, and
`cargo clippy --all-targets -- -D warnings`. Division, square root, GPU kernels,
and throughput/register-pressure measurements remain future work.

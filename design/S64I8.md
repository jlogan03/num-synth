# S64I8: canonical representation and binary64 conversion

This is the phase-one specification and CPU reference contract. It resolves the
open representation questions in [the design handoff](../Synthetic%20Floating-Point%20Arithmetic%20on%20Low-Precision%20GPU%20Hardware.md).
The implementation provides construction and conversion only. Addition,
subtraction, multiplication, FMA, comparisons, GPU kernels, and arithmetic
exception flags remain future work.

## Canonical representation

Use ten **balanced radix-128 digits**, an independent sign, a signed 16-bit
binary exponent, and an explicit classification. Digits are stored most
significant first. For a finite nonzero value define

```text
B = 128
d[i] ∈ [-64, 63], i = 0,...,9
S = Σ d[i] B^(9-i)
2^67 ≤ S < 2^68
E ∈ [-32768, 32767]
x = (-1)^sign S 2^(E-67)
```

Thus the normalized significand is `M = S / 2^67`, with `1 ≤ M < 2`,
and `E = floor(log2(|x|))`. In the handoff's fractional-digit notation this
means `M = (Σ d[i] 2^(-7i)) / 16`: the division by 16 is intentional.
It uses more of the top digit than setting that digit near one, which would
provide only 64 bits with ten digits.

The leading digit lies in `[16, 32]`; this is a consequence, not a substitute
for checking the complete `S` interval. In particular, a leading 16 with a
negative tail or a leading 32 with a nonnegative tail is not normalized.
The sign applies to the positive *whole significand*, independently of the
signs of its balanced digits. There is no internal subnormal class.

The reference `#[repr(C)]` structure contains:

| Field | Storage | Invariant |
| --- | --- | --- |
| exponent | `i16` | `E` for finite values; zero otherwise |
| digits | `[i8; 10]` | balanced digits, most significant first |
| class | `#[repr(u8)]` enum | zero, finite, infinity, or NaN |
| negative | `bool` | independent sign, including specials |
| reserved | `[u8; 2]` | zero |

This occupies 16 bytes (checked by a test). Fields are private; the checked
finite constructor rejects invalid digits and normalization. Raw struct bytes
are not a serialization or GPU ABI contract.

For zero and infinity, all digits are zero. For NaNs, the digits instead encode
the original nonzero 52-bit binary64 fraction as a balanced integer, with no
normalization requirement. This preserves the payload and quiet/signaling bit.
All special values have exponent zero and retain their original sign. There
is exactly one representation per signed zero, signed infinity, or signed NaN
fraction. Bit conversion does not quiet signaling NaNs or raise exceptions;
future arithmetic must specify its own NaN and exception behavior.

## Existence and uniqueness

For an integer `n`, choose the unique residue

```text
r = ((n + 64) mod 128) - 64       (Euclidean modulo)
q = (n - r) / 128 = floor((n + 64) / 128)
n = 128q + r
```

Repeatedly emit `r` from least to most significant. Each step is exact, and
`[-64, 63]` contains precisely one representative of every residue modulo 128.
Therefore the lowest digit is unique; division by 128 and induction prove
uniqueness of every subsequent digit.

Ten digits cover every integer in the interval

```text
L = -64 (128^10 - 1) / 127
U =  63 (128^10 - 1) / 127.
```

Proof of coverage: the all-minimum and all-maximum vectors attain the endpoints.
There are `128^10` distinct vectors by residue uniqueness, and
`U - L + 1 = 128^10`, so no integer in the interval is missing. Since
`U > 2^68 - 1` and `L < 0`, every chosen normalized significand fits exactly.
The decomposition also covers every NaN fraction.

The tail below the leading digit has magnitude at most
`64 (128^9 - 1) / 127 < 128^9`; in fact it is less than `0.504 * 128^9`.
Together with `16 ≤ S / 128^9 < 32`, this proves `16 ≤ d[0] ≤ 32`.
Finally, normalization makes `E` the unique binary binade exponent, and `S`
and its digits are then unique. Noncanonical wide temporaries will need a
separate future type, rather than weakening these stored invariants.

## Precision and range proofs

At each exponent the set of significands is exactly all integers in
`[2^67, 2^68)`. This is **68 significant binary bits**, with spacing
`2^(E-67)` in binade `[2^E, 2^(E+1))`. Every normalized binary significand
with at most 68 bits is representable if its exponent fits. Rounding an exact
value to this grid would have relative error at most `2^-68` within range;
no internal arithmetic rounding operation is implemented yet.

The count `10 × 7 = 70` is a storage digit count, not normalized precision.
For uniform balanced digits, `2^68 - 1 ≤ U < 2^69 - 1`, so a complete
69-bit normalized significand interval cannot fit. The selected 68 bits are
the largest complete interval of the conventional form `[2^(p-1), 2^p)`.
The same convention with eight digits provides 54 significant bits; adding
two digits adds 14 bits, giving **15 bits beyond binary64's 53** in total.

The smallest positive finite value and largest finite magnitude are

```text
min = 2^-32768
max = (2 - 2^-67) 2^32767.
```

For binary64 normals, let the exponent field be `e` and stored fraction `f`.
Then `m = 2^52 + f` and `x = (-1)^sign m 2^(e-1075)`. Set
`E = e - 1023` and `S = m 2^15`. This lies in the canonical interval and
gives exactly the same value. All normal exponents `[-1022, 1023]` fit `i16`.

For binary64 subnormals, `1 ≤ f < 2^52` and `x = (-1)^sign f 2^-1074`.
Let `k = floor(log2(f))`, found using integer leading-zero count. Set
`E = k - 1074` and `S = f 2^(67-k)`. Now `2^67 ≤ S < 2^68` and
`S 2^(E-67) = f 2^-1074` exactly. These exponents span `[-1074, -1023]`.
Consequently every finite binary64 input, including the smallest subnormal
and largest finite value, expands exactly.

## Exact accumulator bounds for future arithmetic

These bounds specify permitted temporaries; they do not implement arithmetic.
For `a,b ∈ [-64,63]`, the tight single-product bounds are

```text
-4032 = (-64)63 ≤ ab ≤ (-64)(-64) = 4096.
```

The positive bound is larger because the digit interval is asymmetric.
`i16` holds an individual product exactly; `i8` does not. Operands must be
widened before multiplication, or use an instruction with a wider accumulator.

For two ten-digit magnitudes, define the schoolbook coefficients

```text
c[k] = Σ a[i] b[j], i+j=k,  k=0,...,18
t[k] = min(k+1, 19-k, 10)
-4032 t[k] ≤ c[k] ≤ 4096 t[k]
```

There are 100 products and 19 raw coefficients, with at most ten products per
coefficient. Thus `-40320 ≤ c[k] ≤ 40960`, and every partial sum in any order
also has absolute value at most `40960`. An `i32` accumulator is exact with
ample headroom. These term-count bounds are conservative for normalized
values; for example, their leading digits cannot be -64. No reliance on such
extra restrictions is needed. Applying a separate product sign gives the
symmetric bound `|c[k]| ≤ 40960`.

Balanced carry propagation proceeds from the lowest coefficient upward:

```text
v[k] = c[k] + incoming_carry
digit[k] = ((v[k] + 64) mod 128) - 64
outgoing_carry = floor((v[k] + 64) / 128)
```

Starting with zero carry, `|carry| ≤ 323` is inductive: if it holds on entry,
`|v[k]| ≤ 40960 + 323 = 41283`, and the quotient endpoints are
`floor((-41283+64)/128) = -323` and
`floor((41283+64)/128) = 323`. The largest absolute intermediate, including
the bias, is at most 41347, so carry propagation also fits `i32` exactly.
Negative carries require **floor division**, not truncation toward zero.
Any final leading carry must be retained; the original 19 slots are not a
bound on the normalized product's digit length. Twenty balanced digits
suffice because the exact positive integer product is below `2^136`, whereas
twenty digits have positive capacity greater than `2^138`.

A raw coefficient accumulator starting at zero can accept at most
`floor((2^31-1)/40960) = 52428` complete products under the conservative
absolute bound without overflow. This is a bound on *unshifted raw sums only*;
it does not reserve carry headroom and does not authorize arbitrary exponent
alignment, FMA accumulation, or unlimited lazy normalization. Each such
operation requires a new bound or periodic propagation with explicit headroom.

The decoded stored significand fits `u128` (and `i128`); even arbitrary
ten-digit balanced input and every Horner prefix have magnitude below `2^70`.
The **full product needs up to 136 bits**, so `u128` is not sufficient for
future exact multiplication. Use wide coefficients or a wider integer.
Use at least `i32` for exponent calculations: two `i16` exponents sum in
`[-65536,65534]` and multiplication normalization can add one. Exponent
differences and subsequent alignment calculations also must be widened first.

## Expansion algorithm

`expand(f64)` immediately calls `to_bits`; `from_bits(u64)` performs the same
operation directly on an encoding. Extract sign, exponent field, and fraction.

1. Classify zero, infinity, and NaN as specified above.
2. For a normal, construct `S = (2^52 + f) << 15` and `E = e - 1023`.
3. For a subnormal, construct `S = f << (67-k)` and `E = k - 1074`.
4. Decompose the positive integer `S` into ten balanced digits using the
   unique residue algorithm. NaN fractions use that same exact decomposition.

Only integer operations and bit reinterpretation are used. The construction
proofs establish representability, so expansion neither rounds nor loses bits.

## Correctly rounded collapse

`to_bits()` returns an encoding; `collapse()` reinterprets it as an `f64`.
For a finite value, reconstruct positive `S` exactly using `i128` Horner
evaluation and work with `E` widened to `i32`. Attach the stored sign to the
final magnitude, including when the result is zero or infinity.

For a positive integer `S` and right shift `h > 0`, let

```text
Q = floor(S / 2^h)
R = S mod 2^h
H = 2^(h-1)
round_even(S / 2^h) = Q + (R > H or (R = H and Q is odd)).
```

Proof: the discarded fraction is `R/2^h`. Comparing it with one half selects
the nearest integer; equality selects the even one. This full remainder test
is equivalent to guard/round/sticky logic and retains all available tail bits.
For a 68-bit `S`, any `h > 68` has `S < H` and rounds to zero without an
oversized machine shift. At `h = 68`, `S = 2^67` is the exact tie to zero.

* **`E > 1023`:** the magnitude is at least `2^1024`, so return infinity.
* **`-1022 ≤ E ≤ 1023`:** round `S / 2^15` once to a 53-bit significand.
  If it becomes `2^53`, shift it right once and increment `E`. Encode the
  exponent and fraction, or infinity if the new exponent is 1024.
* **`E < -1022`:** round directly in binary64 subnormal units, `2^-1074`.
  Since `x / 2^-1074 = S 2^(E+1007)`, use `h = -E-1007`, which is at least
  16. The resulting integer ranges from zero through `2^52`. Integers below
  `2^52` directly encode subnormal fractions (or zero); `2^52` is already the
  encoding of the smallest normal. There is no prior rounding to 53 bits.

At the overflow midpoint, the significand rounds up through `2^53`, so ties
produce infinity. Equivalently, the virtual even successor of the largest
finite number is `2^1024`. At the underflow midpoint `2^-1075`, ties produce
signed zero. At the normal/subnormal midpoint, the even endpoint is the
smallest normal. All three transitions follow the same nearest-even rule.

For zero, infinity, or NaN, directly restore the original fields. Therefore
`S64I8::from_bits(bits).to_bits() == bits` for **every** `u64` bit pattern.
For synthetic values not exactly representable as binary64, collapse is
correctly rounded, not an exact value-preserving conversion.

## Guard precision contract

The stored precision supplies 15 extra bits for values near binary64's normal
range. These bits make exact conversion and local rounding decisions possible;
they do **not** prove correctly rounded future arithmetic.

For an exact normalized result, binary64 rounding needs the retained 53 bits,
the next (guard) bit, and whether *any* lower discarded bit is nonzero, with
the sign and correct exponent. In conventional guard/round/sticky form, retain
two explicit following bits and OR all remaining discarded bits into sticky.
Subnormal output changes where this cutoff lies. Cancellation can expose a
previously low part, so a sticky bit cannot replace an exact cancellation tail.

No fixed number of guard digits by itself guarantees correct rounding of
arbitrary operation chains. For example, an exact result just above a binary64
midpoint can first round to that midpoint at 68 bits, then collapse to the
wrong even neighbor (double rounding). A stored `S64I8` is an exact dyadic
value and carries no provenance or implicit sticky flag. Collapse rounds that
value only, not an unknown earlier exact result.

Future add/mul/FMA must therefore retain an exact wide result or enough
operation-specific residual information to prove a single final rounding
decision. Multiplication needs its full 136-bit product before rounding; FMA
must incorporate the aligned addend before that decision. The 68-bit storage
format alone does not settle these arithmetic requirements.

## Verification

The integration tests use `proptest` and a test-only `num-bigint` oracle.
Production conversion has no dependencies. The oracle places the exact input
and binary64 candidates on a common integer lattice, binary-searches adjacent
positive encodings, compares exact distances, and resolves equal distances by
encoding parity. It uses the virtual overflow endpoint `2^1024` and does not
reuse the implementation's rounding routine or native floating arithmetic.

Coverage includes arbitrary binary64 encodings and NaN payloads; independent
checks of expanded dyadic values and digit invariants; arbitrary canonical
significands and balanced digit vectors; the entire `i16` exponent domain via
random sampling and explicit extremes; random binary64 midpoint neighbors;
every binary64 exponent field with boundary fractions; subnormal leading-bit
boundaries; both signs; ties with even/odd retained significands; sticky-only
changes; rounding carries; underflow, overflow, and normal/subnormal transitions;
invalid constructors; and the 16-byte layout. Sampling supports the proofs
above but is not a claim of exhaustive testing of all binary64 encodings.

Run `cargo test`, `cargo test --release`, `cargo fmt --check`, and
`cargo clippy --all-targets -- -D warnings`.
